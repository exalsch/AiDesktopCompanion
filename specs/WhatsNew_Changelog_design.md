# What's New popup and changelog workflow

Status: design, approved 2026-09-08. Not yet implemented.

## Problem

The app already notices that a newer GitHub release exists (`useUpdateCheck`)
and links to the release page, but once the user has installed the new build
there is nothing in the app that says what actually changed. The release page is
a wall of Conventional Commit subjects generated by `scripts/release-notes.sh`,
which is fine as an audit trail and poor as a "here is what is new for you"
summary.

Two things are missing:

1. A **What's New popup** that appears once after an update and lists the
   user-facing changes, each collapsible so the headline is scannable and the
   detail is one click away.
2. A **discipline and a pipeline** that keeps those entries accurate: every
   user-facing change writes one entry when it is made, and cutting a version
   files those entries under that version rather than leaving them to be
   reconstructed from git log months later.

## Goals

- One human-editable source of truth for user-facing changes.
- The popup shows every release the user skipped, not only the newest one.
- Entries are written at change time, in the same pull request as the change.
- Cutting a version is one command, and the GitHub release body, the popup and
  the file cannot drift apart.
- CI catches a user-facing pull request that forgot its entry.

## Non-goals

- No in-app updater. The existing notify-only flow stays exactly as it is.
- No backfill of the full release history. Versions before this feature stay
  documented in GitHub Releases only.
- No i18n. The app is English-only today.

## Source of truth: `CHANGELOG.md`

A single `CHANGELOG.md` at the repository root. Its grammar is deliberately
small so the parser can stay short and the file stays pleasant to hand-edit.

```markdown
# Changelog

User-facing changes only. See the GitHub releases for the full commit history.

## Unreleased

### Update check on window focus
kind: fix

The app re-runs its update check whenever the main window comes back to the
front, so a build that has been left running for days still notices a release.

## 0.1.23 - 2026-09-07

### Assistant Mode call history
kind: feat

Every Assistant Mode call is now recorded with its duration, model, voice,
token counts and estimated cost. Calls can be pinned so the retention sweep
leaves them alone.
```

Grammar:

- `## Unreleased` opens the pending section. Exactly one such section, always
  present, always first.
- `## X.Y.Z - YYYY-MM-DD` opens a released section. Newest first.
- `### <headline>` opens one entry. The headline is what the popup shows
  collapsed, so it is a short sentence, not a commit subject.
- An optional `kind: feat | fix | perf` line immediately under the heading sets
  the chip shown next to the headline. Anything else, or a missing line, renders
  without a chip.
- Everything after the optional `kind:` line up to the next heading is the
  entry detail: ordinary markdown, rendered when the entry is expanded.

Seed content: an empty `## Unreleased`, plus `0.1.23` and `0.1.22`
reconstructed from `git log` so an upgrade from either of those has something
to show.

## Frontend

### `app/src/changelog/parse.ts`

A dependency-free module, no Vue imports, so it can be exercised by a plain
`node --test` file.

```ts
export type ChangelogKind = 'feat' | 'fix' | 'perf'

export interface ChangelogEntry {
  title: string
  kind?: ChangelogKind
  /** Markdown, may be empty. */
  detail: string
}

export interface ChangelogRelease {
  /** "Unreleased" or a semver string. */
  version: string
  /** ISO date, absent for Unreleased and for a version written without one. */
  date?: string
  entries: ChangelogEntry[]
}

export function parseChangelog(markdown: string): ChangelogRelease[]

/** -1 / 0 / 1. Non-numeric or malformed parts sort as 0. */
export function compareVersions(a: string, b: string): number

/** Releases strictly newer than `seen`, newest first. Unreleased is dropped. */
export function releasesSince(all: ChangelogRelease[], seen: string): ChangelogRelease[]
```

The parser is a line scanner, not a markdown AST walk: split on `\n`, switch on
`## ` and `### ` prefixes, accumulate the rest. Fenced code blocks inside an
entry detail are respected so a `### ` line inside a fence is not mistaken for
a heading.

Malformed input degrades rather than throws. A `##` line that is neither
`Unreleased` nor a version is skipped along with its entries; a `###` before any
`##` is dropped. The popup showing nothing is an acceptable failure mode, a
crashing main window is not.

### `app/src/composables/useWhatsNew.ts`

A module-level singleton, in the same shape as `useUpdateCheck`.

- Imports the file as a string: `import changelogMd from '../../../CHANGELOG.md?raw'`.
  Vite inlines it into the bundle, so there is no fetch at runtime and nothing
  to add to the CSP.
- Parses once at module load.
- Reads `localStorage['adc.whatsNew.lastSeenVersion']`.
  - Missing value: this is a fresh install. Write the current version, show
    nothing. A first-time user does not get greeted with a changelog for a
    version they never upgraded from.
  - Value equal to the current version: nothing to show.
  - Value older than the current version: `releases` becomes every release
    between the two, newest first, and `visible` becomes true.
  - Value newer than the current version (a downgrade, or a hand-edited value):
    treated like "equal", and the stored value is corrected to the running
    version.
- `dismiss()` stamps the current version and hides the dialog.
- `open()` shows the dialog on demand with the newest release preselected, for
  the "read it again later" path. It does not change the stored version.
- Every `localStorage` access is wrapped in try/catch, matching
  `useUpdateCheck` and `CollapsibleCard`. A locked-down webview means the popup
  shows every launch, which is noisy but harmless.

### `app/src/components/WhatsNewDialog.vue`

Main window only. A modal overlay: backdrop, a titled panel, one section per
release, one `ui/CollapsibleCard` per entry.

- `CollapsibleCard` is used without an `id`, so the collapsed state is not
  persisted. That is what is wanted here: the dialog is transient.
- `defaultOpen` is false, so entries arrive collapsed. Entries without a detail
  body render with the chevron suppressed rather than expanding into nothing.
- The `kind` chip goes in the card's existing `aside` slot.
- Detail markdown is rendered with the shared renderer described below.
- Escape, a backdrop click, and the dismiss button all call `dismiss()`.
- Focus moves into the dialog on open and returns on close; the panel is
  `role="dialog"` with `aria-modal="true"`.

### Shared markdown renderer

`MessageItem.vue` currently holds a module-level `markdown-it` + `DOMPurify` +
`highlight.js` singleton in its non-setup `<script>` block, with a plain-escape
fallback for when the dynamic imports fail. The dialog needs exactly that, so
the block moves to `app/src/markdown.ts` exporting `initMarkdownSingleton()`,
and `MessageItem.vue` imports it. Behaviour is unchanged; the point is that one
renderer and one sanitiser configuration serve both call sites.

### Wiring

- `App.vue` mounts `<WhatsNewDialog />` in the main-window branch of the tree
  only. The quick-actions, capture-overlay and busy windows never render it.
- `SidebarNav.vue` makes the version label a button that calls `open()`, so the
  dialog is reachable after it has been dismissed.

## Release side

### `scripts/release-prep.mjs <version>`

Replaces the manual five-file edit that every `chore(release)` commit does today.

1. Validate the argument is `X.Y.Z` (optionally with a `-rc.N` style suffix, to
   match the prerelease detection already in `release-windows.yml`) and that it
   is strictly greater than the current `app/package.json` version.
2. Refuse if `## Unreleased` has no entries, unless `--allow-empty` is passed.
   Cutting a release with nothing to tell the user is nearly always a mistake.
3. Write the version into `app/package.json`, `app/src-tauri/Cargo.toml` and
   `app/src-tauri/tauri.conf.json`.
4. Patch the own-package version in `app/package-lock.json` (the root `version`
   and `packages[""].version`) and in `app/src-tauri/Cargo.lock` (the `version`
   line inside the `[[package]]` block whose `name` is `AiDesktopCompanion`).
   Both are narrow, well-defined edits; the script fails loudly rather than
   guessing if a target is not found exactly once.
5. Rewrite `## Unreleased` to `## <version> - <today, local date>` and insert a
   fresh empty `## Unreleased` above it.
6. Print the files it changed. It does not commit, tag or push; that stays a
   deliberate human step.

### `scripts/release-notes.sh`

Gains a first pass. If `CHANGELOG.md` contains a section for the tag being
released (`## X.Y.Z` for tag `vX.Y.Z`), that section becomes the release body,
with its `### ` headings and details reflowed into a list. Otherwise the
existing Conventional Commit grouping runs unchanged, so tags cut before this
feature, and any tag whose section is missing, still produce a body.

The compare link at the end is appended in both paths.

## CI: `.github/workflows/changelog-check.yml`

Trigger: `pull_request`, types `opened, edited, synchronize, reopened, labeled,
unlabeled`. Plain `pull_request` rather than `pull_request_target`, because the
job needs the head diff and needs no write permissions. `permissions:
contents: read`.

Logic:

1. Read the type from the pull request title, which `semantic-pr.yml` has
   already constrained to Conventional Commits. If it is not `feat`, `fix` or
   `perf`, pass.
2. If the `skip-changelog` label is present, pass with a note.
3. Otherwise require both:
   - `CHANGELOG.md` appears in `git diff --name-only origin/<base>...HEAD`, and
   - the `## Unreleased` section on the head has at least one `### ` entry.
4. On failure, print the expected format and the two ways out (add an entry, or
   apply `skip-changelog`).

This is a new workflow rather than a step in `semantic-pr.yml`, because that one
runs on `pull_request_target` with write permissions and does not check out the
code at all.

## Project memory

`CLAUDE.md` gains a **Changelog** section under Conventions & gotchas:

- Every user-facing change adds one `###` entry under `## Unreleased` in
  `CHANGELOG.md`, in the same pull request as the change.
- The headline is what a user reads in the popup. The detail below it is
  markdown and may be several paragraphs.
- Internal-only work (refactors, CI, deps, docs) adds nothing.
- Cutting a version is `node scripts/release-prep.mjs X.Y.Z`, then commit as
  `chore(release): bump version to X.Y.Z`, then tag.

It goes in the checked-in `CLAUDE.md` rather than a machine-local memory so the
rule binds every session and every future contributor, and so it sits next to
the CI check that enforces it.

## Testing

- `app/src/changelog/parse.test.mjs`, run with `node --test`: a well-formed
  document, an empty `Unreleased`, an entry with no detail, an unknown `kind:`,
  a `### ` line inside a fenced code block, and a malformed `##` heading.
  There is no frontend test runner configured, and adding one is out of scope,
  so this stays a standalone node test invoked directly.
- `npm run build` from `app/` for `vue-tsc` coverage of the new components.
- `scripts/release-prep.mjs` verified against a scratch copy of the five files
  before it is trusted on the real tree.
- The workflow is verified by the pull request that introduces it: the pull
  request is titled `feat(app): ...` and must go green only once `CHANGELOG.md`
  carries its entry.
- Manual: set `adc.whatsNew.lastSeenVersion` to an older version in devtools,
  reload, confirm the dialog lists the intervening releases, that entries
  expand, that dismissing stops it returning, and that the sidebar version label
  reopens it.

## Risks

- **Parser drift.** A hand-written parser and a hand-written file will disagree
  eventually. Mitigated by keeping the grammar to two heading levels and one
  optional metadata line, and by failing soft.
- **Lockfile patching.** Regex edits to `package-lock.json` and `Cargo.lock`
  are the most brittle part of `release-prep.mjs`. Mitigated by requiring
  exactly one match and aborting otherwise, which reduces the failure to a
  message telling the user to edit by hand.
- **`?raw` import path.** `CHANGELOG.md` lives above the Vite root (`app/`).
  Vite serves it in dev only if the file is inside the allowed FS roots, so
  `server.fs.allow` may need the repository root added. If that turns out to be
  awkward, the fallback is a repo-root `CHANGELOG.md` with a thin
  `app/src/changelog/CHANGELOG.md` copied in by a prebuild step, which is the
  build-time variant that was considered and set aside.
